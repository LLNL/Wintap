# P1.1 xUnit Test Harness

**Date:** 2026-06-30
**Status:** Approved
**Author:** Engineer
**Architect Approval:** Approved 2026-06-30

## Purpose
Stand up the project's first xUnit test project and prove the verification gate
works end to end. Until this unit lands, the Developer's only gate is a passing
`dotnet build -c Release` plus a manual run. After P1.1, every unit with
testable behavior ships passing tests filtered by its category trait. This unit
establishes the **per-target test project convention** and ships one **real
test against `WintapMessage`** so the harness is exercised against actual
production code, not a smoke assertion.

## Scope
Create a single new xUnit test project, `tests/Wintap.Tests/`, add it to the
solution, reference the cross-platform `shared/WintapAPI` library, and write one
trait-tagged test that constructs a `WintapMessage` and asserts on a real
member. No other projects are created or modified beyond what is required to
make this project build, reference correctly, and appear in the solution.

## Dependencies
- ADR: `dave-wiki/wiki/decisions/2026-06-30-test-project-structure-and-first-test.md`
  (per-target structure; first test = real `WintapMessage` test; P1.1 stands up
  only `tests/Wintap.Tests/` referencing `shared/WintapAPI`).
- `CLAUDE.md` — Build & Verification section (xUnit, trait tagging, filter
  command).
- Production type under test: `gov.llnl.wintap.collect.models.WintapMessage` in
  `shared/WintapAPI/WintapMessage.cs`.

## Implementation Notes

### Decisions already made (do not re-decide)
- **Placement:** Per-target test projects mirror the agents. P1.1 creates
  **only** `tests/Wintap.Tests/`. The `Lintap.Tests` and `Mactap.Tests`
  siblings are deferred to a future unit (P1.2) — **do not create them.**
- **Reference target:** `tests/Wintap.Tests/` references
  `shared/WintapAPI/WintapAPI.csproj`. It does **not** reference the Windows
  agent `wintap/Wintap.csproj`. This keeps the first test cross-platform and
  free of Windows-only package drag. (Rationale in the ADR; do not deviate.)
- **First behavior:** Construct a `WintapMessage` via its public constructor and
  assert the `MessageType` property equals the `MessageTypeEnum` value passed
  in. This is a real behavior test, not `Assert.True(true)`.

### Project file
Create `tests/Wintap.Tests/Wintap.Tests.csproj` as an SDK-style project:
- `<TargetFramework>net8.0</TargetFramework>`
- `<IsPackable>false</IsPackable>`
- `<Nullable>` and `<ImplicitUsings>` — match the style of surrounding code; if
  unset elsewhere, you may leave them at SDK defaults. Do not let nullable
  warnings break the build; disable nullable if it interferes.
- Package references (current stable versions compatible with .NET 8; these are
  the standard xUnit test stack and are pre-approved for this unit):
  - `Microsoft.NET.Test.Sdk`
  - `xunit`
  - `xunit.runner.visualstudio`
- Project reference: `..\..\shared\WintapAPI\WintapAPI.csproj`

> NuGet note: the three packages above are the standard xUnit harness and are
> approved as part of this instruction. Do **not** add any package beyond these
> three without flagging the Architect.

### Test file
Create `tests/Wintap.Tests/WintapMessageTests.cs`:
- Namespace: use a test namespace such as `Wintap.Tests` (match surrounding
  convention if one emerges; there is none yet, so `Wintap.Tests` is fine).
- Add `using gov.llnl.wintap.collect.models;` to reach `WintapMessage`.
- One `[Fact]` method, tagged with the unit trait:
  ```csharp
  [Trait("Category", "P1.1")]
  ```
- The test must:
  1. Construct a message:
     `new WintapMessage(DateTime.UtcNow, 1234, WintapMessage.MessageTypeEnum.Process)`
     (the public constructor is
     `WintapMessage(DateTime eventTime, int processId, MessageTypeEnum eventSourceName)`).
  2. Assert `MessageType == WintapMessage.MessageTypeEnum.Process`.
  - You may additionally assert `PID == 1234` to strengthen the test; optional
    but encouraged. Do not assert on `EventTime`/`ReceiveTime` (they are
    transformed to FILETIME / set to `DateTime.Now` internally and are not the
    point of this unit).

### Solution wiring
Add `tests/Wintap.Tests/Wintap.Tests.csproj` to `Wintap.sln`. The solution uses
the **legacy non-SDK format** with explicit project GUID blocks. Adding the
project requires:
- A `Project("{FAE04EC0-301F-11D3-BF4B-00C04F79EFBC}") = "Wintap.Tests", "tests\Wintap.Tests\Wintap.Tests.csproj", "{NEW-GUID}"` block.
- Matching entries in `GlobalSection(ProjectConfigurationPlatforms)` for the
  configurations the solution defines (Debug/Release across Any CPU/x64/x86/ARM64),
  following the pattern used by `WintapAPI` (`{056C2F16-...}` maps every config
  to `Any CPU`).
- Prefer letting tooling generate this (e.g. `dotnet sln Wintap.sln add
  tests/Wintap.Tests/Wintap.Tests.csproj`) so the GUID and config entries are
  written correctly, then verify the block appears. If editing the `.sln` by
  hand, mirror the `WintapAPI` entries exactly and generate a fresh GUID.

## Acceptance Criteria
1. `tests/Wintap.Tests/Wintap.Tests.csproj` exists, is SDK-style, targets
   `net8.0`, references `shared/WintapAPI/WintapAPI.csproj`, and references the
   three approved xUnit packages.
2. `tests/Wintap.Tests/WintapMessageTests.cs` exists with one `[Fact]` tagged
   `[Trait("Category", "P1.1")]` that constructs a `WintapMessage` and asserts
   `MessageType == WintapMessage.MessageTypeEnum.Process`.
3. `dotnet build -c Release` succeeds for the solution (no new errors).
4. `dotnet test --filter "Category=P1.1"` runs and reports **exactly the P1.1
   test(s)** as passing — i.e. the trait filter selects the test and it passes.
5. Running `dotnet test --filter "Category=DOESNOTEXIST"` selects **zero**
   tests (confirms the filter is real, not a no-op). Document this in the audit.
6. `Wintap.sln` contains a `Project(...)` block and matching
   `ProjectConfigurationPlatforms` entries for `Wintap.Tests`; the project
   builds as part of the solution.

## Test Command
```
dotnet test --filter "Category=P1.1"
```
(Solution build prerequisite: `dotnet build -c Release`.)

## Out of Scope
- **Do not** create `tests/Lintap.Tests/` or `tests/Mactap.Tests/` — deferred
  to P1.2.
- **Do not** reference `wintap/Wintap.csproj` (the Windows agent) from the test
  project — reference only `shared/WintapAPI`.
- **Do not** modify any production source under `wintap/`, `shared/`, or
  `platform/` except the **single** necessary change of adding the test project
  to `Wintap.sln`. No edits to `WintapMessage.cs` or any other production file.
- **Do not** write tests for agent logic, ETL, Esper, DuckDB, or any behavior
  beyond the one `WintapMessage` construction test.
- **Do not** add CI / GitHub Actions / pipeline wiring.
- **Do not** add any NuGet package beyond the three named xUnit-stack packages.
- **Do not** introduce shared test base classes, fixtures, or helpers — one
  test class, one fact.
